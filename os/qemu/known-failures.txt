# Units that are allowed to be failed at the end of the QEMU boot, one per line:
#
#   <unit>   <kind>   reason
#
# kind "qemu" is a difference of the virtual machine (not a defect); kind "bug" is a defect in a
# shared file that smoke.py reports as a known failure until it is fixed. Delete a line when its
# cause is gone: smoke.py warns when a listed unit did not fail.
#
# eitri-camera.service is not listed: with no camera its ConditionPathExists=/dev/eitri-cam skips it
# (inactive/dead) and multi-user.target is not delayed. klipper, moonraker and klarity are not listed either: with the
# data seed and the first-run setup they must be active (smoke.py checks it); klippy reports the missing MCU, which is
# not a unit failure.
eitri-prepare.service     qemu  no boot slot: QEMU boots the kernel directly, so there is no eitri.slot=/rauc.slot= on the command line and eitri-update refuses (correct).
eitri-verify.service      qemu  same cause as eitri-prepare.service (no boot slot under QEMU)
